## Limitations

* Single machine, `local[*]` Spark: no network shuffle, so this measures engine overhead and parallelism on one host, not cluster scalability.
* Spark timings include Parquet writes and the extra actions used to count outputs.
* Peak RSS for Spark includes the whole JVM heap reservation (bounded by `SPARK_DRIVER_MEMORY`), so it reflects configuration as much as data size.
* The pandas implementation hashes rows in Python (`sha256` per row), which is a deliberate parity choice, not the fastest possible pandas code.
* Results vary with CPU, disk, Docker Desktop VM limits and background load.
